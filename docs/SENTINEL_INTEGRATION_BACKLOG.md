## Frozen exclusions and risks

- No schema/migration/Compose/DB dependency, durable adapter, Sentinel worker executable, ingest/query endpoint, UI wiring or live provider call in S00. Interfaces and pure preflight checks are not persistence, wire validation, queue durability or authorization infrastructure.
- Guard live capabilities are not established by merged code or historical scanner fixtures. S01-S08 do not require Guard live integration; S09 public feeds can proceed without inventory. Keep GRD-020/021 unavailable until producer acceptance.
- Current identity includes mutable workspace name and user ID; rename/transfer/team sharing needs owner migration policy. No silent case folding or transfer. Reusing Canvas authorization currently entails fresh provider checks; do not cache indefinitely or create nested auth-store exclusive locks.
- Contract validators use typed internal DTOs; S02/S10 need strict unknown-input validators, operation-specific rights/consent and endpoint security. Future Guard proof must be server-resolved, never browser-supplied. Dedupe keys are tested, durable dedupe is not implemented.
- PostgreSQL connection health is not worker health or monitored-source health. External delivery is at least once unless provider idempotency/receipts establish more; send acceptance alone is not delivery. Controlled tests remain labeled and never establish production monitoring.
- Existing UI textual inconsistencies about auth/source availability are recorded in architecture; broad copy/auth rewrites are excluded. Preserve the original UI and demo behavior through future narrow seams.
