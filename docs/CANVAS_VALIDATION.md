## Coverage

Unit tests assert App/Pages routes including groups/dynamic/catch-all/index, method export syntax, source line evidence, concrete imports vs installed-only SDKs, wrapper chain direction, package metadata, monorepo stability, fixture C with custom encrypted-filesystem auth and no invented PostgreSQL, malformed/unknown/giant/binary sources, path traversal, credential/store exclusions, symlink/junction escape, time/byte/count limits, normalization/dedup/evidence downgrade, immutable manual merge/reconciliation, filters, stable cyclic layout, source/overlay scope failures, unavailable/stale/partial response behavior, scoped persistence, Trust confirmation/observation separation, three workflow plans, state deletion reconciliation, model JSON limits/references and export redaction.

Canvas browser tests use the **actual UI in an isolated test-only Next host** (`tests/canvas/fixture`, localhost port 3214). They cover demo graph/list/keyboard/edge inspection, filters/environment/layout/reset; real offline source evidence and no demo findings in snapshot; manual node/relationship/note undo/redo + demo reload persistence; Trust edits and untested plan; workflow states/transitions/invariants + not_executed plan and no external HTTP requests; malformed/empty recovery and grouping; light/dark responsive screens at 1440, 1280, 390 px and scoped axe WCAG A/AA checks on graph/explorer/inspector/Trust/workflow UI.

Canvas screenshots and traces are generated under ignored `test-results/canvas/`; legacy traces under `test-results/canvas-legacy/`; HTML report under `tests/canvas/playwright-report/canvas`. Legacy tests write tracked `evidence/` screenshots by their existing design; only those test-generated replacements were restored to HEAD in this worktree after verification, preserving the original evidence files. The test host has no auth proxy or production source endpoints. A passing test here does not prove authenticated project/session integration. Browser automation and axe are not human assistive-technology testing; graph interactions retain a structured list/table alternative. Real multiuser persistence, cross-device history and cloud/provider behavior remain unverified.

## Issues found and corrected

- Demo browser persistence initially accessed localStorage before rejecting a non-demo scope. Scope now validates first; unit regression passes.
- TypeScript Node CLI initially needed `.ts` imports incompatible with the unchanged shared tsconfig. A Canvas-only Node loader now resolves internal extensionless imports; shared compiler options stay unchanged.
- Mobile explorer's height cap squeezed component buttons behind filters. Removed the cap and gave the component list its own scroll area; all target widths/themes pass the targeted rerun.
- A transient syntax error during branch/metadata adapter refinement broke the concurrent legacy test run. Fixed and revalidated before final stable test runs.
- Accessible connection list is separate from the legacy component list so existing component selection remains unambiguous. Synthetic Locked → Edited text remains available independently of its Forbidden badge.
- Security overlay responses validate shape, scope, simulated mode and internal action hrefs. A failed adapter does not destroy the base graph.
- The fixture host initially lacked the production document title; the unchanged legacy accessibility test caught it. The host now reuses production metadata, and all three selected legacy tests pass.
- Root ESLint originally included generated bundles from the nested fixture `.next` directory (871 generated-code errors). Added only that exact output path to global ignores; lint passes without changing application rules.

## Limits and remaining integration work

See [INTEGRATION_BACKLOG.md](INTEGRATION_BACKLOG.md) for CAN-001–017. Offline parser limitations and budgets are detailed in [CANVAS_ARCHITECTURE.md](CANVAS_ARCHITECTURE.md). Workflows/Trust are useful local modeling features; no live verification, HTTP test, real findings, deployed database or monitoring is inferred from defining a model. Current expected policy edits always remain untested. Authenticated sources, server persistence and evidence-bearing live Trust/Integrity result contracts require owner integration.

The internal fixture selector displays reproducible pre-analyzed source examples, not an uploaded or connected user repository. The CLI performs actual deterministic parsing. No repository scripts are executed. Demo localStorage contains only manual annotations, positions and editable policy/workflow models, not generated code/graph/findings. Snapshot edits do not persist after changing source/reloading without an injected workspace persistence adapter.
