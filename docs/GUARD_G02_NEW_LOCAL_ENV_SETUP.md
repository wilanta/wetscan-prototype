## Reproduce

```
# 1. database (refuses if the container already exists; port must be free, not 5432/55432)
node --conditions=react-server --import tsx scripts/guard-g02-local-env.ts provision --port 55434
node --conditions=react-server --import tsx scripts/guard-g02-local-env.ts verify      # read-only identity/RLS/privilege proof

# 2. scanner image and fresh measurement (qualification expires after ONE hour; run nothing else meanwhile)
node --import tsx worker/guard/installation/build-context.ts .local/g02-install      # only if the image is missing
export G02_INSTALL_DOCKER=<absolute docker.exe>
ROOT=$(node --conditions=react-server --import tsx scripts/guard-g02-local-env.ts runtime-root)   # new private root
node --import tsx worker/guard/installation/qualify.ts .local/g02-install --full
node --conditions=react-server --import tsx worker/guard/installation/measured.ts <report.json> <root>

# 3. exact-scope policy: one repository, branch, engines sast,sca,secrets,iac,sbom, no container
node --conditions=react-server --import tsx scripts/guard-g02-local-env.ts config <root> "<workspaceId>" <repositoryId> main

# 4. start the app (Guard disabled), references from the helper
eval "$(node --conditions=react-server --import tsx scripts/guard-g02-local-env.ts env)"
export GUARD_PRODUCT_CONFIG_FILE=<root>/product.runtime.json GUARD_PRODUCT_ENABLED=0
npm run guard:dev
```

Only for the supervised acceptance window: restart the same process with `GUARD_PRODUCT_ENABLED=1`, and restart it with `0` afterwards. Never enable it globally.

Stop/start the database: `guard-g02-local-env.ts stop|start`. Backup: `docker exec wetscan-g02-local-pg pg_dump -U postgres -Fc wetscan_dev_guardg02 > backup.dump` (the bootstrap password file is the credential; do not paste it). Safe reset of **only this environment** (destroys its data, owner approval required): remove the container `wetscan-g02-local-pg`, the volume `wetscan-g02-local-pg-data`, the `WetScanGuardG02` directory, then provision again. Never run broad Docker cleanup.

## GitHub sign-in requirements

The real product login is used (no `gh auth login`, no copied cookies). `APP_URL` is `http://localhost:3000`, so open the app at `localhost`, not `127.0.0.1`. The GitHub App (`wetscan-local`) must be installed on the repository, and the repository must be in the owner's selected list: after onboarding this is changed through `POST /api/onboarding {action:"repositories", repositoryIds:[…]}` (kept existing ids plus the new one). That path was a no-op for completed profiles until Fix #20.
