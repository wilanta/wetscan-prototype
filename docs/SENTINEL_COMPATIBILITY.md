Canonical storage/cache/dedupe scope is the tuple **`[mode, workspaceId, projectId]`**, encoded without delimiter collisions. No browser grant accepted. `authorizeSentinelProject` calls the existing `authorizeCanvasProject` each time, then derives/checks scope. Its test double proves propagation; existing Canvas tests cover actual authorization code using provider fixtures. Neither proves current live GitHub access in this task.

**Storage decision for approval:** one local PostgreSQL instance, `sentinel` module ownership and module-neutral `platform` connection/transaction/job lease/outbox primitives. Sentinel project records bind authorized identity, not a new GitHub registry. Auth encrypted filesystem and Canvas cache remain. No Guard tables, migrations or implicit enrollment. Guard can later implement `PersistencePort`/`QueuePort` through separate owner-reviewed adapters. SnapshotPort/SandboxPort remain independent prerequisites.

**Worker decision for approval:** future `worker/sentinel` entry point handles telemetry, detections, TTL, feeds, and outbox. Separate process, module-discriminated queue, DB role and budget from future Guard scanner worker. Sharing primitives never permits claiming another module's jobs. Proposed local Sentinel limits: concurrency 2, batch 25, poll 1 s, lease 30 s/heartbeat 10 s, handler 20 s, max 5 attempts, process memory 256 MB; review under H10/H01. Guard's scanner sandbox is not supplied by these limits.

**Reserved namespaces:** telemetry `auth.failed`, `http.suspicious_path`, `http.request`, `ghost.decoy_triggered`; Guard pipeline `release_evaluated`, `remediation_retested`; inventory `dependency_inventory`; Canvas `runtime_incidents`. Schema version 1, independent numeric record revisions and repository commit SHA. Incompatible changes need a new version and owner review.
