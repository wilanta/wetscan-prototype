## 1. Integrate real scanner execution

Reuse the existing pinned scanner integrations and normalization code.

Implement actual worker-backed scanning of authorized, immutable repository snapshots.

Engines:

### A. Opengrep SAST

- JS/TS/Node/Next.js as initial supported ecosystems.
- Versioned and checksum-verified rules.
- Bounded execution.
- Structured findings and severity/confidence.
- Real source path and line references.
- Scanner/version/rule provenance.
- Positive and negative fixture tests.
- Actual authorized repository acceptance.

### B. OSV SCA

- Supported dependency manifests and lockfiles.
- Exact package/ecosystem/version inventory.
- OSV advisory identifiers and aliases.
- Fixed-version recommendations where available.
- CVSS information when provided by trusted advisory evidence.
- Unknown severity/license explicitly preserved.
- Separate dependency inventory from vulnerability findings.

### C. Gitleaks

- Repository secret scanning.
- Real scanner execution in the sandbox.
- Redacted evidence only.
- No matched secret value in database/UI/logs.
- Accurate scanner errors and coverage limitations.
- Tested positive and negative results.

### D. Trivy IaC

- Authorized IaC source scanning.
- Supported file type detection.
- Configuration findings and remediation guidance.
- Versioned rules and evidence.
- No Terraform apply, cloud mutation or infrastructure deployment.

### E. Container and SBOM

- Digest-pinned image references only.
- Explicit authorized image scope.
- SBOM generation using a reviewed format such as CycloneDX or SPDX.
- Package and vulnerability provenance.
- Never build or run an arbitrary Dockerfile as part of scanning.
- Do not claim container scanning when no approved image/runtime is available.

## 2. Scanner orchestration

Integrate scanners with the G01 queue and worker.

Required:

- Quick, Standard and Full profiles.
- Deterministic engine selection.
- Execution ordering and bounded parallelism.
- Engine-specific limits and cancellation.
- Partial-failure handling.
- Retries for transient infrastructure failures.
- No fabricated clean results.
- Immutable commit and snapshot verification.
- Scan history across restarts.
- Normalized findings and evidence persistence.

Every engine must independently report:

- queued
- running
- completed
- failed
- timed_out
- skipped
- not_configured
- not_applicable

Preserve the meanings in the existing contracts.

## 4. Required end-to-end flow

Authenticated GitHub user
→ Authorized repository
→ Pinned commit
→ Guard scan request
→ Durable queue
→ Isolated worker
→ Real scanner CLI
→ Normalized findings

Verify at least one specifically authorized test repository with controlled vulnerable and fixed revisions.

Do not scan arbitrary repositories or production targets without authorization.

## 5. Quality and security

Test:

- Vulnerable and clean source fixtures.
- Multiple supported file types.
- Real scanner output normalization.
- Missing scanner.
- Scanner timeout and crash.
- Scanner cancellation.
- Secret redaction.
- Partial scans.
- Stale commits.
- Duplicate scan requests.
- Wrong project/workspace.
- Persisted job history.
- RLS and isolated findings.
- Sandbox restrictions.
- Live/Demo separation.

Run typecheck, lint, complete unit tests, production build, browser regressions and applicable real PostgreSQL/scanner integration tests.

If scanning an actual authorized repository remains blocked by a sandbox or permission gate, do not claim live scanning completed.
