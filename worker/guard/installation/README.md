# G02 scanner installation components

Trusted wrapper/control code and Docker recipe only; these are not a second scanner engine or a live-repository acceptance claim. Binary assets come from pinned official GitHub releases, with publisher SHA256 verified before extraction. Rules are pinned official source blobs. The OSV snapshot must have a pinned official object generation/integrity metadata; npm is the initially installed ecosystem. No host binary execution, remote installer script, owner source, credentials or Docker config enters the context.

Use the existing GUARD_G02_LIVE_OPERATOR.md procedure. Build contexts, downloaded binaries/data, ownership records and measured installation/qualification artifacts belong under ignored .local/g02-install, never Git. Local built images are addressed only by sha256 image ID and re-inspected before execution. No registry publication is needed. Legacy G01 image validation is unchanged.

The control path is for explicitly authorized synthetic installation tests only. Containers always run as65532, readonly/no-network, with bounded CPU/memory/PIDs/time/output and exactly one readonly source fixture mount. A rule match in this fixture is a real CLI installation check, not a real customer scan. Do not promote controls/results or create qualification PASS artifacts before physical tests and owned cleanup actually pass. No PostgreSQL/G01 job/permit is involved.

Public release/rules/database provenance is pinned in SOURCES.json; downloaded assets remain ignored. qualify.ts uses only fixed server-owned commands and controlled files, records actual spec/duration, and preserves failed reports. measured.ts refuses missing/expired/failed controls, scanner failures, changed commands, excess runtime or unknown cleanup. It writes exclusive hash-named artifacts only into an already ACL-verified new G02 directory and performs a Docker metadata recheck. It does not generate a database approval, repository policy, enqueue or scan permission. Artifacts expire from measurement time after one hour; do not re-date old evidence.

Operational OSV alone allows2048MiB because its full npm offline database exceeded256MiB in the actual test. The legacy G01 validator still rejects that limit, and other operational engines stay256MiB. Current setup uses45s per engine,1CPU,64PIDs,2MB stdout/stderr budget and16MiB noexec tmpfs. No system-wide resource limit or retry mechanism was changed.
